# Contributing To MONACOPS Reference Architectures

Thank you for your interest in improving the MONACOPS public documentation repository.

This repository is for vendor-neutral reference architectures, security patterns, evaluation guidance and operating models for Agentic AI Operating Systems and autonomous AI workforces.

## What We Welcome

- Clearer explanations of architecture patterns
- Stronger security, governance or observability guidance
- Vendor-neutral integration patterns
- Better Mermaid diagrams
- Evaluation metrics and test scenarios that can be reproduced without private data
- Documentation fixes, terminology improvements and accessibility improvements

## What We Do Not Accept

- Secrets, credentials or private keys
- Client names, client data or confidential implementation details
- Proprietary source code
- Unsupported performance claims
- Fabricated benchmarks
- Vendor-specific marketing copy presented as neutral architecture guidance
- Content that encourages bypassing human approval for sensitive actions

## Contribution Process

1. Open an issue describing the proposed change when it affects architecture, security posture or repository scope.
2. Keep pull requests focused and reviewable.
3. Use plain technical language and avoid hype.
4. Preserve vendor neutrality unless the context is explicitly an example.
5. Include security and human-approval implications when adding new workflows.
6. Update diagrams and evaluation guidance when architecture changes affect them.

## Documentation Standards

Architecture documents should include:

- Business problem
- Scope
- Actors
- Data sources
- Integrations
- Orchestration flow
- Human approval points
- Security boundaries
- Observability
- Failure modes
- Evaluation metrics
- Limitations
- Mermaid architecture diagram
